# Requirements: Gamebloke v5.0 Deterministic Core API and Installed Consumer Proof

**Defined:** 2026-11-23
**Core Value:** A fresh Gamebloke instance, given a named GBA profile, content, and timed logical input, produces deterministic, observable, evidence-backed machine behavior, and every result says exactly what it proves and what it does not.

This is the owner-approved scope for GSD milestone v5.0, not a Gamebloke
software release claim.

## v1 Requirements

### Public Core API

- [x] **API-01**: A C consumer can create and destroy independent machine instances through a versioned opaque API without depending on `gbl_machine` or other private structures.
- [x] **API-02**: A consumer can select the supported `agb`, direct-start, ROM-only profile and load, unload, or reset content; rejected profile or content operations report a documented status and preserve the documented machine and buffer state.
- [x] **API-03**: A consumer can submit timestamped logical input and advance an instance within a caller-specified work bound, with progress and refusal results reported explicitly.
- [x] **API-04**: A consumer can read raw video and audio through caller-owned buffers and structured result metadata that identifies the profile, guest progress, machine time, observations, supported behavior, and claim limits.
- [x] **API-05**: Invalid arguments, insufficient output capacity, unsupported requests, and exhausted work bounds are refused with documented state and buffer postconditions before partial mutation.

### Installed Consumer and Evidence

- [x] **CONS-01**: A small C consumer builds and runs against the installed public headers and libraries after relocation outside both the source and build trees, without accessing private machine structures.
- [x] **EVID-01**: The consumer runs a rights-reviewed, original BIOS-free diagnostic whose manifest records source, revision, build recipe, digest, license/notices, BIOS mode, expected results, and permitted use; no commercial ROM, BIOS dump, or private save is required.
- [x] **EVID-02**: Fresh consumer runs assert guest semantics and literal raw video/audio expectations independently of output hashes, while hashes are used only to establish identity or repeatability.

### Integration Evaluation

- [x] **INT-01**: A fit report evaluates LibFuturo against the real Gamebloke API and relocated consumer, including input timing, bounded advancement, output ownership, and evidence semantics; adoption and contract changes remain separate decisions.

## v2 Requirements

Deferred until a real consumer or separate owner decision promotes them:

### Machine and Cartridge Capabilities

- **CART-01**: Implement the explicitly selected backup device a named consumer needs, with device identity bound to the mounted cartridge rather than inferred from a title or filename.
- **CPU-01**: Expand ARM7TDMI instruction and source-qualified timing coverage beyond the current declared subset.
- **QUAL-01**: Qualify a named profile against physical hardware using authorized devices, fixtures, and independent expected results.

### Product Integration and Distribution

- **HOST-01**: Evaluate a side-by-side Gamebloke route in Playstead while preserving the managed mGBA route unless the owner separately approves replacement.
- **DIST-01**: Publish a package or release only after rights, licensing, package readiness, qualification claims, and publication authority are resolved.

## Out of Scope

| Feature | Reason |
|---------|--------|
| SRAM/FRAM, Flash, EEPROM, RTC, or other backup-media implementation | v5.0 proves a consumer boundary first; device selection follows an evidenced consumer need. |
| Playstead code changes or replacement of its managed mGBA route | Route integration is a separate product decision after the installed-consumer proof. |
| Claiming retail compatibility superiority or hardware accuracy | The milestone establishes API and deterministic model evidence only. |
| Bundled BIOS bytes, commercial ROMs, private saves, or unlicensed fixtures | Rights policy; none may enter source control or public CI. |
| Host file persistence, wall-clock scheduling, controller discovery, windowing, or A/V presentation inside the deterministic core | These services remain outside the portable machine implementation. |
| Automatic adoption of LibFuturo or a new runtime dependency | Fit is evaluated against the real consumer before any dependency or contract decision. |
| Public package publication or software release | Requires separate rights, licensing, qualification, package-readiness, and owner-authority gates. |
