## User story

**As** the owner/developer, **I want** the inventory gate to catch every way a test can silently not run, and every negative control to be unable to pass by accident, **so that** a green verdict means every expected test actually ran. (Phase story: see 01-01-PLAN.md.)

Decisions implemented (index in 01-01-PLAN.md): D-01, D-02, D-03, D-04, D-05, D-06.

<objective>
Expand the tracer's gate into the full inventory contract with one negative-control wrapper and a meta-control, driven by junit shapes synthesized at test time, then pin the core and runner contract (D-05, D-06) with unit tests and a no-host-includes gate.

Purpose: VERIF-03 needs every omission shape to fail; VERIF-02 needs a wrapper that makes negative controls trustworthy. Every later gate reuses this wrapper.
Output: `inventory.*`, `nc.meta.*`, `core.*`, and `runner.*` tests green in `cmake --workflow --preset ci`.
</objective>

Complete scripts/check-junit.sh to the full RESEARCH.md Pattern 3 contract (D-04, VERIF-03): add `inventory: duplicate`, `inventory: disabled` (status `disabled`, always a failure because CTest records no reason), `inventory: skipped-not-allowed` (status `notrun` with a `<skipped` child on a line without `skip-ok`), `inventory: skipped-no-reason` (skip-ok test skipped but its `<system-out>` has no `SKIPPED: ` text), `inventory: empty-junit` (zero testcases). For every skipped test print `SKIPPED <name>: <skipped message attribute> | <reason text after SKIPPED: >`. A skip-ok test that runs and passes is allowed. Report every finding before exiting 1 (do not stop at the first); usage errors exit 2. Parse with awk `split()` on `<testcase ` (system-out can contain semicolons, so do not use CMake lists). Print reason codes in the stable form `inventory: <code>: <name>`.

cmake/ExpectFail.cmake (D-03, VERIF-02): define `function(gbl_expect_fail)` with keywords `COMMAND` (multi), `REGEX`, optional `EXIT`, optional `WORKING_DIRECTORY`. Before running, set `ENV{ASAN_OPTIONS}` to the existing value plus `detect_leaks=0`. Run via execute_process capturing stdout and stderr together. If the exit code is 0: `message(FATAL_ERROR "expect-fail: gate PASSED but must fail (negative control broken)")` plus the output. If `EXIT` is given and differs: fail with `expect-fail: wrong exit`. If the output does not match REGEX: fail with `expect-fail: failed for the wrong reason` plus the wanted regex, exit code, and output. On success print `expect-fail: ok: /<REGEX>/ (exit <rc>)`. Also define `function(gbl_expect_pass)` (positive control: exit 0 required, output printed on failure as `expect-pass: gate FAILED on clean input`). Script mode: when `-DCMD=` is defined, call gbl_expect_fail with `COMMAND ${CMD}` followed by the elements of an optional `-DARGS=` list, `REGEX ${REGEX}`, and optional `EXIT`. Because gbl_add_test parses COMMAND with cmake_parse_arguments, a `;` inside one add_test argument is split; callers therefore pass the program as `-DCMD=<program>` and each extra argument through `-DARGS=` using `|` as the separator, which script mode converts to a list. Never assert an exact exit code for sanitizer controls; `EXIT` exists only for documented program exit codes such as the runner's 2.

tests/harness_case.cmake: a CMake -P driver taking `-DCASE=<name>` plus `-DSRC=` and `-DBIN=`. Always rebuild the case sandbox `BIN/nc/<case>` from scratch. For the junit cases, write `BIN/nc/<case>/junit.xml` and `BIN/nc/<case>/inventory.txt` with file(WRITE) from CMake bracket strings (`[==[ ... ]==]`) holding hand-written XML in the exact CTest shapes recorded in RESEARCH.md Pattern 3 (testsuite element with tests/failures/skipped/disabled counts, testcase elements with name, classname, time, status, and the skipped/failure children and system-out). The inventory lists three synthetic tests in the inventory format, one marked skip-ok, plus a `post`-labelled line that the exclude regex removes. Each case then includes cmake/ExpectFail.cmake and calls gbl_expect_fail or gbl_expect_pass on `sh SRC/scripts/check-junit.sh BIN/nc/<case>/junit.xml BIN/nc/<case>/inventory.txt post` with the matching `inventory: <code>` regex; case `no_junit` points at a path that does not exist. Case `configure_mismatch` writes a registered-list file and expects InventoryCompare.cmake in script mode to fail with `inventory: configure-mismatch`; case `unsorted` writes an out-of-order inventory and expects `inventory: unsorted`. Case `meta` runs ExpectFail.cmake in script mode on `-DCMD=${CMAKE_COMMAND} -DARGS=-E|true` and requires that wrapper run to exit non-zero with `gate PASSED but must fail`. Cases `add_test_bad_name` and `add_test_no_labels` (W-2, D-04) write a minimal sandbox project `BIN/nc/<case>/proj/CMakeLists.txt` with file(WRITE): `cmake_minimum_required(VERSION 3.25)`, `project(gbl_nc NONE)` (no compiler detection, so it configures in about a second), `set(GBL_LANE ci)`, `enable_testing()`, `include(<SRC>/cmake/GblTests.cmake)`, then one malformed registration: `gbl_add_test(NAME Bad.Name LABELS unit COMMAND true)` for bad_name, `gbl_add_test(NAME ok.name COMMAND true)` for no_labels. Each runs gbl_expect_fail on `${CMAKE_COMMAND} -S <proj> -B <proj>/build -G Ninja` with REGEX `gbl_add_test: bad-name` or `gbl_add_test: no-labels`. The refusal is a FATAL_ERROR at the call, so it fires before the deferred inventory compare and the sandbox needs no inventory file; the positive companion is every real configure of this repository, whose valid registrations pass the same checks. Generating the shapes at test time keeps this plan within its file budget and keeps every shape next to the case that uses it.

tests/harness.cmake: register, all with command `${CMAKE_COMMAND} -DCASE=<case> -DSRC=${CMAKE_SOURCE_DIR} -DBIN=${CMAKE_BINARY_DIR} -P ${CMAKE_SOURCE_DIR}/tests/harness_case.cmake`: `inventory.nc.missing`, `inventory.nc.extra`, `inventory.nc.duplicate`, `inventory.nc.failed`, `inventory.nc.skipped_not_allowed`, `inventory.nc.skipped_no_reason`, `inventory.nc.disabled`, `inventory.nc.empty_junit`, `inventory.nc.no_junit`, `inventory.nc.configure_mismatch`, `inventory.nc.unsorted`, `inventory.nc.add_test_bad_name`, `inventory.nc.add_test_no_labels` (labels `control,inventory`), `inventory.pos.pass` and `inventory.pos.skip_reported` (labels `inventory,positive`; skip_reported runs the skipped_allowed case), and `nc.meta.passing_gate_fails_wrapper` (labels `control,meta`).
